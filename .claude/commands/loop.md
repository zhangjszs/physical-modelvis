# 自主工作循环

启动自主工作循环，按照以下步骤循环执行，直到所有任务完成或遇到需要人工决策的阻塞。

## 循环步骤

### 1. 读取任务清单
读取 `TASKS.md`，找到第一个状态为 `- [ ]`（未开始）的任务。如果没有未开始的任务，跳到步骤 8。

### 2. 标记开始
将该任务从 `- [ ]` 改为 `- [~]`（进行中）。

### 3. 实现任务
按照 `AGENTS.md` 中的项目约定实现该任务：
- physics-core 模型继承 `PhysicsModelBase`，通过 `registerModel` 注册
- 使用解析解（除电磁复合场用 Boris 数值积分）
- TypeScript strict mode
- 中文 UI 文本和文档
- 参考 `experiments/` 目录下对应章节的实验内容

### 4. 验证
依次执行以下检查，全部通过才算通过：
```bash
# physics-core 测试
cd physics-core && npm test

# visualization 类型检查
cd ../visualization && npx tsc --noEmit

# visualization 构建
npm run build
```

### 5. 处理结果

**全部通过：**
1. 将任务标记为 `- [x]`（已完成）
2. 提交代码（见步骤 6）
3. 回到步骤 1 处理下一个任务

**验证失败：**
1. 分析失败原因，尝试修复
2. 最多重试 2 次，每次修复后重新执行步骤 4
3. 2 次后仍失败：将任务标记为 `- [!]`（阻塞），在任务下方记录失败原因，跳到下一个任务

### 6. 提交规范
每个任务完成后创建独立提交：
- 遵循项目现有提交风格（参考 `git log --oneline -5`）
- 提交消息格式：`<type>: <任务简述>`
- type 包括：feat（新功能）、fix（修复）、refactor（重构）、test（测试）、docs（文档）
- **不要使用 `--no-verify` 跳过钩子**
- 不要提交 `.env`、密钥等敏感文件

### 7. 循环
回到步骤 1。

### 8. 结束条件
当没有 `- [ ]` 任务时，输出总结：
- 已完成：N 个任务（列出标题）
- 阻塞：M 个任务（列出标题和原因）
- 需决策：K 个任务（列出标题）

## 暂停条件
遇到以下情况时停止循环并报告：
1. 需要人工决策的设计选择（标记为 `- [?]`）
2. 连续 3 个任务阻塞
3. 发现 TASKS.md 中的任务描述不明确，无法继续

## 任务清单格式
```markdown
- [ ] 任务标题
  - 描述：具体要做什么
  - 涉及文件：预期修改的文件/目录
  - 参考：experiments/ 中的对应章节
```

状态标记：
- `- [ ]` 未开始
- `- [~]` 进行中
- `- [x]` 已完成
- `- [!]` 阻塞（附原因）
- `- [?]` 需人工决策
