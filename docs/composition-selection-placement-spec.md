# 自由组合实验台：器材选中与自由放置交互规格

- 状态：Draft v1（待确认）
- 日期：2026-10-28
- 范围：`visualization/src/components/composition/*`、`visualization/src/store/compositionStore.ts`
- 上游：#100（旋转编辑/回放）、#101（预设模板）、#93（场线密度）
- 核心不变式：**保持"自由组合"**——器材可自由增删、按住拖动、松手重算、场线实时跟手、模板一键布置。
  本规格只改"怎么选中"和"怎么放下"，不改物理模型、不改 `FieldSource` 数据结构、不改模板语义。

## 0. 结论摘要

| 用户问题 | 代码层根因 | 改进方向 |
| --- | --- | --- |
| 密集/堆叠时选不中指定器材 | 拾取只取 `hits[0]`，没有候选集合；半透明匀强磁场区仍会挡住射线；没有列表入口；没有悬停反馈 | 候选栈 + 同点重复点击循环 + 器材列表 + 悬停高亮 + 点击/拖拽分离 |
| 随意放置不可控 | 调色板点击即按伪随机位置落子；无预览、无合法性判断、无越界约束、无高度编辑、无撤销；拖拽与点击共用同一条指针路径 | 拖入预览 + 落点吸附 + 软/硬合法性 + 自动避让 + 高度可调 + 撤销/重做 |

一句话目标：**用户指哪选哪、放哪是哪、放错能退。**

---

## 1. 目标与非目标

### 1.1 目标（用户可感知）

1. 在任意相机角度、任意遮挡关系下，用户能用 **≤2 次同点点击** 或 **1 次列表点击** 选中指定器材。
2. 点击与拖拽分离：**没有移动的点击永远不改变位置、不触发重仿真**。
3. 从器材面板拖入舞台时，用户**先看到落点和合法性**，再决定是否放下。
4. 新器材不会无缘无故叠在一起，也不会被放到桌面之外。
5. 放错、拖错、删错可以 **Ctrl+Z 逐步撤销**。
6. 高度（物理 z）可调，用户能表达"把电荷放进盒子里偏上的位置"这类意图。

### 1.2 非目标

- 不引入刚体碰撞、重力、堆叠稳定性等物理语义；"堆叠"只是视觉/布局，物理仍是点源叠加。
- 不做自动实验设计或智能推荐布局；"自由组合"仍是主路径。
- 不做多人协作、云存档、账号体系。
- 不重构 3D 引擎、不改 `boris3d` / `fields3d` / 模板数值。
- 不在本阶段做多选、框选、编组（列入 P2）。

### 1.3 成功度量

| 指标 | 目标 |
| --- | --- |
| 密集场景选中成功率（6 个点电荷，中心距 ≤0.05 m） | 20/20 次，≤2 次点击或 1 次列表点击 |
| 无效重仿真 | 纯点击（位移 <4 px）触发 `recompute` 次数 = 0 |
| 放置落点误差 | 器材中心与指针投影点偏差 ≤1 个网格（0.05 m） |
| 越界器材 | 拖放/自动布局后器材 AABB 越出台面次数 = 0 |
| 撤销一致性 | 连续 20 次增删移，撤销后状态与操作前逐项相等 |
| 拖拽流畅度 | 20 个器材场景下指针跟手无明显掉帧（不新增每帧 store 写入） |

| 现象 | 代码位置 | 根因 |
| --- | --- | --- |
| 点调色板即落子，位置不可选 | `CompositionLab.tsx:156-167` `addSource(kind)` | 没有把指针位置传进去；`addSource` 的位置参数从未被 UI 使用 |
| 位置是伪随机数 | `compositionStore.ts:165` `-0.4 + ((nextId * 0.13) % 0.8)` | 按自增 id 算偏移，与用户意图无关 |
| 连续添加会叠在一起 | 同上；两次添加仅相距 0.13 m | 点电荷视觉半径 0.1 m，两个球会明显相交；且不检查已有器材 |
| 没有落点预览 | `CompositionLab.tsx:156-167` | 没有 ghost、没有合法性反馈、没有 Esc 取消 |
| 只能在同一高度平面拖动 | `CompositionStage.tsx:337-338` `planeY` 固定 | 高度 z 一旦创建就不可改；检查器也没有 z 字段 |
| 默认高度语义不一致 | `compositionStore.ts:28-73` 各类 `height` 硬编码 | 点电荷/极板离桌约 5 cm、导线轴心 20 cm、线圈/场区贴地；"放在桌上"没有统一基线 |
| 不能撤销 | `compositionStore.ts` 无 history | 误删/误拖只能手工恢复 |
| 吸附只有绝对网格 | `compositionCoords.ts:39-41` | 没有相邻器材磁吸、没有对齐参考线 |

> 结论：两个问题不是"手感不好"，而是**缺少一层可枚举的交互模型**：选中缺少候选集合，放置缺少"预览—校验—提交"状态机。

## 3. 问题一：密集/堆叠物体的准确选中

### 3.1 用户故事

1. 作为教师，我把两个点电荷放得很近做电偶极子，想单独改其中一个的电量。
2. 作为学生，我把点电荷放进匀强磁场区，想点中电荷而不是盒子。
3. 作为教师，我斜着看实验台，前面的线圈挡住了后面的磁铁，我想选中被挡的那个。
4. 作为触屏用户，我手指粗，点不中 0.1 m 的小球。

### 3.2 必须解决的交互需求

#### P0（本阶段必须）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| S-1 | 拾取候选栈 | 一次射线命中的所有器材去重成一个有序候选集合，而不是只取第一个 |
| S-2 | 同点重复点击循环 | 在同一个屏幕点（4 px 内）重复点击，依次选中候选 1→2→3→1；换点则重置为 1 |
| S-3 | 容器穿透 | 半透明匀强磁场区不抢占盒内实体的拾取；只有点在盒边界/箭头上且没有实体候选时才选中盒 |
| S-4 | 器材列表 | 右侧新增"器材列表"，点击行即选中；行 hover 与 3D 高亮联动 |
| S-5 | 点击/拖拽分离 | 位移 <4 px 视为点击，只选中不移动、不重仿真；超过阈值才进入拖拽 |
| S-6 | 悬停反馈 | 鼠标下有权材时显示 grab/pointer 光标 + 轻量轮廓；无器材时恢复默认 |
| S-7 | 选中态可见 | 选中器材显示高对比包围盒 + 名称徽标（"点电荷 #3"），与列表行同步 |
| S-8 | 可读命名 | 列表与徽标使用"类型 + 序号"，不展示内部完整 id |

#### P1（紧随其后）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| S-9 | Alt+点击候选菜单 | 同点多候选时在光标旁弹出列表（Blender 式），触屏用长按 500 ms 触发 |
| S-10 | 小目标/触屏兜底 | 几何射线无命中时，用屏幕空间距离 ≤12 px（鼠标）/ ≤24 px（触屏）找最近器材中心 |
| S-11 | 锁定/隐藏 | 列表行提供锁定（不可选中/不可拖动）与临时隐藏，避免误操作大件器材 |
| S-12 | 聚焦选中 | 列表双击或按 F，相机平滑飞到器材，解决"拖丢后找不到" |

### 3.3 候选排序规则（实现契约）

候选按以下顺序排序，保证"可预期"而不是"看运气"：

1. **实体优先于容器**：`uniform-field-zone` 的盒体面（不是箭头）排在所有非容器候选之后。
2. **可见面距离近者优先**：同一优先级内按射线距离升序。
3. **同距离按器材在 store 中的顺序**：保证循环顺序稳定、可测试。
4. **同一器材多面命中只保留最近一次**：按 `sourceId` 去重。
5. **当前选中项作为"粘性"起点**：若它仍在候选集中，下一次同点点击从它的下一位开始，而不是跳回第 1 个。

实现建议：抽成纯函数 `buildPickStack(hits, sources): PickCandidate[]`，不依赖 three.js 场景状态，便于单测。
`PickCandidate = { id, kind, distance, insertionIndex, isContainer }`。

### 3.4 交互细则

| 操作 | 结果 |
| --- | --- |
| 单击器材 | 选中候选 1；显示包围盒 + 名称徽标；列表对应行高亮 |
| 同一点再次单击 | 选中候选 2；光标旁短暂显示 "2/3" |
| 同一点第三次单击 | 选中候选 3；再到 1，循环 |
| 换一个点单击 | 重新从候选 1 开始 |
| Alt+单击（P1） | 弹出候选列表，鼠标移动高亮、点击确认、Esc 关闭 |
| 长按 500 ms（触屏，P1） | 同 Alt+单击 |
| 单击空白 | 取消选中；不改变相机 |
| 按住拖动 >4 px | 选中并拖动；松手 commit 一次 |
| 点击列表行 | 选中；3D 中高亮并保持当前相机 |
| 列表行 ↑/↓ + Enter | 键盘切换选中 |
| Delete | 删除选中（保留现有行为） |
| Esc | 关闭候选菜单 / 取消放置模式（不删除器材） |

### 3.5 预期效果（验收场景）

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| A-1 | 6 个点电荷中心距 ≤0.05 m | 任意指定一个，≤2 次同点点击或 1 次列表点击选中；选中徽标与列表一致 |
| A-2 | 点电荷位于 0.4×0.3×0.3 m 匀强区内部 | 点击电荷屏幕位置选中电荷；点击盒边缘空白选中盒 |
| A-3 | 磁铁被极板挡住 | Alt+点击或列表可选中磁铁；普通点击选中极板（可见面优先） |
| A-4 | 单击器材后原地松手（含 1-2 px 抖动） | `sources` 位置不变；`result` 引用不变；`fieldLineRevision` 不变 |
| A-5 | 拖动竖直朝向的条形磁铁 | 首帧高度不跳变（\|Δz\| ≤0.001 m） |
| A-6 | 触屏点不中 0.1 m 小球 | 24 px 内可选中；长按出候选列表 |
| A-7 | 键盘用户 | 仅用列表 + ↑/↓ + Enter 可完成选中与删除 |

### 3.6 实现提示

- **不要用材质自发光做唯一选中反馈**：区域盒半透明、极板浅色，自发光对比不足；用 `Box3.setFromObject` + `BoxHelper`（P0）或 `EdgesGeometry` 描边（P1）。
- **容器穿透不要靠"调透明度"**：Raycaster 不看 opacity。给区域盒面片打 `userData.pickRole = 'zone-volume'`，在候选栈里降权；箭头保持正常优先级。
- **点击/拖拽阈值放在 Stage 本地状态**，不要写进 store，避免每次 pointermove 触发 React 重渲染。
- **hover 射线每帧最多一次**（rAF 合并），且不与拖拽同时跑。
- **循环状态用 `{ screenX, screenY, ids, index }` 记录**；候选集合变化（增删器材）时重置。
- **列表是第二真源**：它必须与 3D 选中双向同步，且不引入第三份状态，直接读写 `selectedId`。

## 4. 问题二：随意放置

### 4.1 具体问题表现

1. **位置不是用户选的**：点"＋ 点电荷"后，器材出现在 `-0.4 + (id×0.13 mod 0.8)` 的位置，用户还得再拖一次。
2. **连续添加会叠**：第二个点电荷只比第一个远 0.13 m，两个半径 0.1 m 的球明显相交；用户看到的"一堆球"无法区分。
3. **没有"要放哪里"的预演**：手指抬起前不知道会落在哪、会不会压住别的器材、会不会掉出桌面。
4. **只能平面拖动**：高度 z 创建后不可改；想做"让电荷从盒子上方进入"只能改代码或换模板。
5. **放错不可逆**：误删、误拖没有撤销；"清空实验台"一键全没。
6. **边界失控**：拖拽平面无限延伸，器材可以被拖到 8×8 m 台面之外，相机里再也找不到。
7. **吸附是"绝对网格"，不是"相对关系"**：想让两个器材对齐只能靠肉眼估 0.05 m。
8. **拖拽与点击抢同一条指针路径**：想选中却轻微移动，器材跑了；想拖拽却先触发选中高亮，反馈混乱。

### 4.2 期望的放置体验（设计原则）

1. **先预览，后提交**：指针移动时就有半透明 ghost 跟随，颜色表示合法/非法。
2. **落点即所见**：松手后器材中心 = ghost 中心 = 指针在台面的投影（吸附后）。
3. **意图优先于碰撞**：允许"把电荷放进场区""把线圈套在磁铁外"这类有意包含；只拦截明显的实体互穿和完全重合。
4. **物理诚实**：点电荷在物理上是点源，视觉球体只是标记；**不能用视觉半径当碰撞体**，否则会禁掉合法的电偶极子。
5. **每一步可退**：增、删、移、改高度都可撤销；拖拽一次只记一条历史。
6. **不强迫用户改变习惯**：单击调色板仍能"一键添加"，只是改为自动避让；拖拽是增强路径，不是唯一路径。

### 4.3 交互规格

#### 4.3.1 两条添加入口

| 入口 | 行为 |
| --- | --- |
| 单击调色板按钮 | 快速添加：在默认锚点附近做螺旋避让搜索，选第一个合法槽位；添加后选中并短暂显示落点脉冲 |
| 从调色板拖出（>4 px） | 进入放置模式：生成 ghost，跟随指针；松手在舞台内且合法才创建；拖回面板/Esc/右键取消 |
| 放置模式中单击舞台 | 提交放置；非法时 ghost 抖动并提示原因，不创建 |
| 放置模式中按 Esc | 取消，不创建，恢复原选中 |

> 保留"单击即添加"是为了不破坏现有课堂节奏；拖拽用于需要精确落点的场景。

#### 4.3.2 落点与吸附

- 指针 → 与器材"基准平面"求交（默认物理 z = 该器材默认工作高度；P1 支持 Shift 改高度）。
- 位置吸附到 0.05 m 网格（沿用 `snapVector`）。
- 邻近磁吸（P1）：当距离另一个器材的锚点 <0.08 m 时，吸附到其中心线/边缘对齐，并显示对齐辅助线。
- 台面边界：8×8 m，按器材 footprint 内缩 0.05 m 夹取；越界时 ghost 变红并贴边。
- 高度：P0 沿用各类型默认高度；P1 增加检查器"高度 z (m)"字段与 Shift+拖拽垂直调整。

#### 4.3.3 合法性分级

| 级别 | 条件 | 反馈 |
| --- | --- | --- |
| 合法 | 在台面内；与同类器材中心距 ≥0.02 m；无实体互穿 | 绿色 ghost，可放下 |
| 警告（允许） | 视觉球体相碰但中心距 ≥0.02 m；放入/套住容器类器材；与其他器材距离 <0.1 m | 黄色 ghost + "靠近放置"提示，可放下 |
| 非法 | 中心重合（<0.02 m）；实体几何明显互穿；越出台面；NaN/零尺寸 | 红色 ghost + 原因，松手不创建 |

> 容器类（`uniform-field-zone`）与实体类之间**永远不判非法**，只做提示；这是"自由组合"的核心表达力。

#### 4.3.4 自动避让（单击添加）

- 以默认锚点为中心，按 0.05 m 步长做环形/螺旋搜索，半径 0.15→1.2 m。
- 目标：与已有实体的中心距 ≥0.2 m（保证可点击），且在台面内。
- 找不到时：允许最小间距 0.1 m，并提示"台面较满，已就近放置"；不静默叠放。
- 算法必须是纯函数、确定性（同样输入同样输出），便于单测。

#### 4.3.5 撤销/重做

- `Ctrl+Z` / `Ctrl+Shift+Z`，面板提供按钮；Mac 兼容 `Cmd`。
- 历史快照只存布局：`sources`、`selectedId`、`particle`、`duration`、场线开关/密度、`activeTemplateId`；**不存 `result`**（大对象），撤销后惰性重算。
- 拖拽期间不记历史，松手 `commit` 时记一条。
- 上限 50 条；超出丢最旧。
- P1 只覆盖增/删/移/改高度/旋转；参数输入框的逐字符编辑暂不逐步记录（合并为一次）。

#### 4.3.6 其他

- 修正提示文案："左键空白处旋转 · 滚轮缩放 · 右键平移 · 点击选中 · 拖动布点"。
- 选中后可 `Ctrl+D` 复制（P2），偏移 0.1 m 并自动避让。
- 器材列表显示"点电荷 #3"而非 `point-charge-3`。

### 4.5 实现提示

- `addSource(kind, position?)` 已支持显式位置（`compositionStore.ts:109,163`），**不需要改签名**；UI 只需把落点传进去。
- ghost 复用 `makeSourceMesh`，但必须克隆材质并设 `transparent/opacity/depthWrite`，避免污染真实器材材质。
- 合法性判断抽纯函数 `validateDrop(source, sources, bounds)`，与渲染解耦；footprint 用世界 AABB（考虑朝向），不要用视觉球体半径。
- 拖拽时只在吸附后的位置**真的变化**时写 store（现有 `moveSource` 已这么做），并沿用"不重仿真"契约。
- 撤销快照用浅拷贝数组即可；`sources` 内对象是不可变替换（现有 reducer 风格），不需要深拷贝。
- 自动避让不要用 O(n²) 大循环；器材数量级 <50，螺旋槽位 × 现有器材的简单双重循环足够。
- 不要让放置模式与 OrbitControls 抢事件：ghost 阶段禁用 controls，结束恢复。

### 5.5 调研结论（只取交互，不取代码）

1. **选中要"可枚举"**：Unity 的"同点循环"、Blender 的"Alt+点击菜单"、three.js 编辑器的"层级列表"，三者解决的是同一个问题；我们三者都缺。
2. **列表不是备选，是基础设施**：它同时解决遮挡、触屏、键盘可达和"器材被拖丢"。PhET 的元件库、Algodoo 的对象面板都印证了这一点。
3. **放置必须"预览 + 校验 + 可撤销"**：沙盒类产品没有一个是"点按钮直接随机落子"的；Physion/Algodoo 都是"画/拖到目标位置"。
4. **吸附要能临时关闭**：ElectricFieldMotionSimulator 的 Alt 关闭吸附是低成本、高收益的细节；否则磁吸会"抢位置"。
5. **相机操作与物体操作必须分离**：3D Physics Sandbox 把"拖物体"和"转视角"都绑左键，是最常见的翻车点；我们必须用"命中判断 + 4 px 阈值 + 空白处才转视角"。
6. **选中反馈不要只靠材质**：半透明容器和浅色实体上，自发光对比不足；描边/包围盒更可靠。

## 6. 约束

### 6.1 架构与数据

- `FieldSource` 联合类型与 `PlacedSource` 结构保持不变；新增的选中/放置状态只进 store 的 UI 字段或组件本地状态。
- `moveSource` **不触发重仿真**的契约必须保留（`compositionStore.test.ts` 已锁定）。
- `loadTemplate` 的单次 commit 语义必须保留（`fieldLineRevision` 只 +1）。
- `addSource(kind, position?)` 已具备落点参数，直接复用；不要为放置再造一条创建路径。
- 场线只依赖 `sources`，选中/悬停**不得**触发 `fieldLineRevision`。

### 6.2 物理

- 不引入碰撞、重力、堆叠稳定性；点电荷是点源，视觉球体不是碰撞体。
- 放置校验只做"布局合法性"，不做物理可行性判断（例如电荷能否悬空、导线是否通电）。
- 任何高度改动都必须走引擎重算，不得在渲染层伪造轨迹。

### 6.3 性能

- 不新增运行时依赖；首屏入口 chunks gzip 仍 ≤70 kB。
- hover 射线每帧最多一次；拖拽期间不做 hover。
- 拖拽期间不写 store（除非吸附位置真的变化），不重建场线（沿用 100 ms 节流与 1× 封顶）。
- ghost 只创建一次，移动时改 transform；不要每帧重建几何/材质。
- 撤销快照不复制 `result`；上限 50 条。

### 6.4 兼容与可访问性

- 鼠标、触控板、触屏、手写笔都要可用；不得依赖右键或 hover 才能完成核心操作。
- 器材列表必须可 Tab 聚焦、↑/↓ 切换、Enter 选中；canvas 不是唯一入口。
- 中文 UI；沿用现有 `btn` / `PanelSection` / 设计 token，不新造一套视觉。
- 提示文案与实际键位一致（修正"右键旋转"）。

### 6.5 工程门禁

- TypeScript strict；禁止新增 `as unknown as` 双重强转；射线命中数据用 `userData` + 类型守卫读取。
- 纯逻辑（候选排序、footprint、自动槽位、合法性）必须先有单测；测试放在 `visualization/tests/composition/`。
- 新交互需扩展 `scripts/verify-composition-interaction.mjs`（Playwright，真实画布像素 + DOM 断言），并保持零 console error。
- 提交前 `npm run precheck` 全绿；测试数量变化后 `npm run count:sync`。
- 不破坏现有 4 个 headless 探针与首屏体积门禁。

## 8. 待决问题（需要产品/教学侧确认）

1. **高度是否是教学变量？** 如果课堂需要"让电荷从盒子上方进入"，高度必须是一等公民（z 输入 + 标尺）；否则只做 Shift 拖拽即可。
2. **有意重叠的边界**：电偶极子（两个电荷很近）必须允许；实体互穿（磁铁插进极板）是否只警告不拦截？建议"警告 + 允许 Alt 强制"。
3. **触屏是否是主要上课设备？** 决定长按候选菜单与 24 px 兜底的优先级；如果以鼠标为主，S-9/S-10 可降到 P2。
4. **是否需要多选/框选？** 当前单选中 + 列表已能覆盖大部分课堂操作；多选会显著增加状态与撤销复杂度。
5. **撤销覆盖范围**：只覆盖增删移/旋转，还是也覆盖参数逐字符编辑？建议先只覆盖结构性操作。
6. **器材命名**：是否允许用户重命名（"电荷 A / 电荷 B"）？如果只显示序号，需确认序号在删除后是否保持稳定。
7. **区域盒拾取策略**：容器穿透是否会误伤"我要选盒子本身"？建议保留"点边界/箭头 + 列表"两条路径，并在首次穿透时给一次轻提示。
