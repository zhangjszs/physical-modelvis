### 批次 C · EquipmentStage 3D 背景 token 化 + 双主题探针

- **症状**：`EquipmentStage.tsx` L167/L186 两处 `isDark ? 0x0b1020 : 0xf8fafc` 写死 3D 背景/雾效；
  `verify-portal-tokens.mjs` 只验证 OCR 弹窗与 CSS 令牌，不验证 Canvas/3D 的实际颜色消费。
- **诊断**：3D 背景值 `#0b1020` / `#f8fafc` 与 `--bg`（亮色 #eef2fb）不等值，不能直接复用 `--bg`，

  由纯函数 `resolveStage3DBackground(theme)` 派生。
- **探针两处误判与纠正（证据链）**：
  1. 首版把 clear color 按「线性色」比较，实测 `#0b1020` 读到 `0.0431,0.0627,0.1255`（= 11/255,16/255,32/255）。
     读 three r185 `WebGLBackground.setClear` 源码确认：`color.getRGB(_rgb, getUnlitUniformColorSpace(renderer))`，
     clear color 上报的是**归一化 sRGB**，不是 Color 内部线性值 → 修正比较基准。
  2. 首版选「碰撞」场景后直接探测 2D 画布，实测仍是 WebGL：所有 123 场景都有 3D rig，
     `useSceneRig.is3DScene = hasSceneRig(sceneId)` 为 true → 必须显式点「2D 板书」才卸载 StageRenderer。
     修正后探针真实走到 `SimulationCanvas` 的 `drawCollisionScene`。
- **处方**：
  1. `EquipmentStage` 两处背景/雾效改 `resolveStage3DBackground(theme)`，组件内 `0x0b1020`/`0xf8fafc` 清零；
  2. `equipment-stage.test.tsx` mock `THREE.Scene` 记录实例，断言暗色 background/fog `getHex()=0x0b1020`、
     亮色切换后同一 Scene 变为 `0xf8fafc`（证明主题切换不重建 Scene）；
  3. `theme-tokens.test.tsx` 增加 EquipmentStage 源码守卫；
  4. `verify-portal-tokens.mjs` 增加：3D clear color 双主题断言（容差 0.02）、碰撞场景 2D 板书双主题非空、
